Objetivos

  • Gestionar credenciales de acceso sin depender del área de Compras
  • Actualizar el Encargado HUB cuando hay rotación de personal
  • Activar códigos proveedor nuevos con agilidad
  • Tener visibilidad del estado de cada solicitud enviada
  • Resolver incidencias de acceso sin llamar al soporte

Frustraciones

  • El proceso de credenciales pasa por Compras — no tiene control directo
  • No sabe si su solicitud fue aprobada, rechazada o está en espera
  • Cuando el HUB anterior ya no trabaja, hay que reiniciar todo el proceso
  • El Excel de registro es manual y propenso a errores
  • No hay un canal claro para actualizar datos de contacto

Comportamientos

  • Lee los SOPs cuando los encuentra — pero no siempre los tiene a mano
  • Prefiere el correo formal sobre WhatsApp para dejar evidencia
  • Coordina con el Encargado HUB para validar que las credenciales llegaron
  • Hace seguimiento activo de sus tickets — escribe si no tiene respuesta
  • Conoce los procesos mejor que el HUB, pero no tiene acceso al portal

Necesidades del sistema

  • Estado en tiempo real de sus solicitudes (credenciales, activaciones)
  • Guía clara del proceso de actualización de Encargado HUB
  • Historial de solicitudes anteriores trazable
  • Confirmación automática cuando una solicitud avanza de estado
  • Saber exactamente qué información falta para no ser rechazado

Escenario típico de uso

1

Un vendedor nuevo necesita acceso al portal — Roberto inicia la solicitud de credenciales

Emoción: seguridad — conoce el proceso

2

Llena el Excel, lo manda a soportehub — y espera sin saber si llegó bien

Emoción: incertidumbre — no hay confirmación

3

Compras rechaza el formulario porque falta el nombre del Gerente Comercial

Emoción: frustración — el error era evitable con validación previa

4

Corrige y reenvía — días después el HUB confirma que recibió las credenciales

Emoción: alivio — pero el proceso tardó más de lo necesario
